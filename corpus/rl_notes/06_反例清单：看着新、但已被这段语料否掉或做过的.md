## 5. 反例清单：看着新、但已被这段语料否掉或做过的

| 做法 | 为什么别做 |
| --- | --- |
| 再发明一个 `*PO`，只换粒度（token→segment→turn） | PACT 已证明 RLOO 的粗粒度信号在期望梯度上与 token 级一致；RLDS 自认在 2/4 个基准上无显著增益 |
| 给零方差组注入教师解 / oracle hint | ZPPO 明确指出会破坏 on-policy 假设；BOPTR 给出可补差距上限约 3–5 pp |
| 用"配对 rollout"来加速学习 | Luck Is Not Skill 给出反例：奖励对比方差下降 ≠ 梯度方差下降，预注册判据未通过 |
| 用熵选 token 做信用 | GMTS 证明熵跨答案不一致、梯度幅度更准——熵是**相关而非因果** |
| "联合优化 RL + 蒸馏"比顺序好 | Sequential Beats Joint（2609.04108）：OPD-then-RL 胜过加权相加与教师调制，联合优化会相互干扰 |
| 靠单点提升 + 单次运行宣告胜利 | 核心集 277 篇里只有 9 篇报种子；`shuffled` 负对照在 TOL=2 时都能拿到 8.3% 成功率，噪声就是这么大 |
| 只报 pass@1 | ES vs GRPO 表明 Pass@1 与 Pass@k 可分别优化；只报一个会掩盖覆盖率损失 |
| 把 rubric 当纯解药 | Rubric Dropout 直接测出训练判官与金标发散（ResearchQA −22 分） |
| 认为"奖励模型越大越好" | B 桶冲突：1.7B 探针可胜 8B 生成判官；2M 隐藏态验证器可胜 55M 文本验证器 |
