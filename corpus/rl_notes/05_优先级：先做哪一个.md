## 4. 优先级：先做哪一个

评分依据：**信息量 / 本地可行性 / 成本**。本地资源约束是硬约束——单卡 RTX 4080 16 GB（WSL2，桌面占 ~1 GB）、vLLM 只能用于生成不能用于训练、Qwen2.5-0.5B~1.5B + GSM8K/MATH 是现实范围。

| 排名 | 提案 | 为什么先做 | 成本 | 可能的"全灭"结局 |
| --- | --- | --- | --- | --- |
| **1** | **P7 可核查性 2×2 判决实验** | 一次实验判决整个过程奖励方向；CPU/单卡数小时；负对照天然内建 | 极低 | 若 A≈B>C，则"可核查性"叙事被证伪（但省下整个方向的投入） |
| **2** | **P1 CreditBench（已跑通）** | 尺子做出来就永久可用；已有 3 区制结果与 8 条测试 | 极低（CPU） | 结论可能是"粒度不重要"——仍然是重要结论 |
| **3** | **P3 DriftAudit** | 单卡上 TIM 天然存在；你手头已有 Score Centering 原文；负对照最干净 | 低（需 vLLM+HF 双引擎） | 若打乱 Δ 也有效，则说明测量无价值 |
| **4** | **P2 零方差组的悲观利用** | 0.5B 上全错组比例极高，现象显著；与 PAC/CGE 可直接对比 | 低 | 悲观项可能压死探索 |
| **5** | **P8 算力兑换率** | 回答"RL 到底创造了多少能力"这个元问题，产出可复用的评测协议 | 低 | 结论可能是"RL 只是重加权"——这会动摇很多论文 |
| 6–8 | P5 激励相容裁判 / P4 投资组合审计 / P6 MAP-Elites | 各有明确判决实验，但需要更细的任务构造 | 中 | — |
| 9–11 | P9 梯度方差设计 / P10 分区正交 / P11 世界模型反事实 | 理论更漂亮，工程量更大，且 P11 依赖环境构造 | 中高 | — |

### 一周执行计划（单卡，全部可在本机完成）

| 天 | 任务 | 产出 |
| --- | --- | --- |
| D1 | 读 `credit_oracle.py`，把合成任务换成**多步算术链**（每步可核验），接入 GSM8K 子集 | oracle 环境 v2 |
| D2 | 跑 P7 的 2×2（合成任务上，0.5B） | 三格结论：A/B/C 组准确率 + 曲线 |
| D3 | 若 P7 通过 A>B，把可核查性预算接入 RLVR 训练脚本；若否，转 P2 | 判决记录（两种结果都入库） |
| D4 | P1 的学习型信用头（用 oracle 信用监督 token 特征） | 信用头 + 与启发式的相关性对比 |
| D5 | P3：搭 vLLM 生成 + HF 训练的漂移测量管线，注入三档失配 | 漂移-稳定性曲线 |
| D6 | P2：GSM8K 上"丢弃 vs 遮蔽 vs 悲观下界"等算力对比 | 有效梯度信息 vs GPU-小时 |
| D7 | P8：等算力下 RL vs best-of-n vs 混合 | gain decomposition 表 |

**共同方法论护栏（不管做哪个提案都要遵守）**：
1. **预注册**：先写下判据再跑（`Luck Is Not Skill` 的教训——跑完再定判据等于没定）。
2. **配对随机数 + ≥3 种子**：277 篇里只有 9 篇做到，做到就是优势。
3. **等算力**：报告 GPU-小时；对齐有效学习率、有效 batch、熵预算（F 桶的核心批评）。
4. **每个实验带负对照**，且负对照必须**有鉴别力**（我给的 `test_buggy_dp_is_detected` 就是这个模式：故意写错的 DP 必须被测试抓出来）。
5. **三条坍缩曲线必报**：语义熵、长度分布、pass@k。只报 pass@1 会漏掉"分数涨、可监控性跌"（TAME 2609.24243 实测 RL 后 CoT 可监控性掉约 30 点）。
6. **区分实测与估算**，估算写清依据与不确定度。
