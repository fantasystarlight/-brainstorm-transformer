## 附录 B　本文生成物清单

| 文件 | 内容 |
| --- | --- |
| `extract_rl.py` | 从 43 份日报 JSON 抽取 RL 语料（产出 `rl_corpus.json` / `rl_corpus.md`） |
| `bucket.py` | 按主题分 8 桶（`slices/A_*.md … H_*.md`）+ 核心集 `slices/CORE.md` + `rl_titles.txt` |
| `credit_oracle.py` | P1 的可运行 oracle 对拍（tabular，CPU 约 36 秒，`--help` 有全部旋钮） |
| `credit_oracle_report.json` | 三个区制 × 六个估计器 × 三个种子的实测结果 |
| `test_credit_oracle.py` | 8 条硬断言，含"故意写错的 DP 必须被抓出"的鉴别力测试 |
| `flowchart.py` | 由本文件里的锚点生成流程图（PNG/MMD/TXT 三份同源） |
| `docs/flow_proposals.{png,mmd,txt}` | 6 缺口 → 11 提案 → 首要判决动作 |
| `docs/flow_experiment.{png,mmd,txt}` | 判决实验决策树（以 P7 的 2×2 为例） |
| `test_flowchart.py` | 图守卫：锚点仍在、无缺字形、三份产物同源、结构形状 |
| `knowledge_graph.py` | **知识图谱生成器**：单一数据源 → PNG / Mermaid / 纯文本 / JSON |
| `knowledge_graph.json` | 图谱数据（8 域 / 52 知识点 / 48 关系 / 44 方法 / 4 争论 / 11 提案），可直接给别的工具消费 |
| `docs/kg_overview.{png,mmd,txt}` | 全景：缺口 → 提案 → 知识域（颜色＝知识域） |
| `docs/kg_knowledge_a.{png,mmd,txt}` | 知识点 A：目标函数与信任域 / 信用分配 / 奖励与验证 |
| `docs/kg_knowledge_b.{png,mmd,txt}` | 知识点 B：探索与覆盖 / 系统与漂移 / 理论与诊断 |
| `docs/kg_knowledge_c.{png,mmd,txt}` | 知识点 C：方法论 / 跨域迁移源（节点上标注流向的提案） |
| `docs/kg_conflicts.{png,mmd,txt}` | 四条未解决争论的双方、反例与判决实验 |
| `docs/kg_methods.{png,mmd,txt}` | 方法图谱：八个域的代表方法 + arXiv id + 证据状态（共识/冲突/空白） |
| `test_knowledge_graph.py` | 图谱守卫：文档锚点 + **语料锚点（每个 arXiv id 必须真实存在）** + 产物同源 |
| `RL新策略头脑风暴.md` | 本文（附录 C 就是图谱节点的文字版） |

**图的读法**：`flow_proposals` 的左中右三列分别是"缺口 / 提案 / 首个判决动作"，连接线表示该提案针对哪个缺口、以及第一件该做的实验；`flow_experiment` 是执行决策树——**每个节点都对应本文里的一句原文**（图生成器会校验锚点，所以图不会与文字漂移）。

**一条自检命令**：`python3 test_credit_oracle.py && python3 test_flowchart.py && python3 test_knowledge_graph.py`（全部通过；若文档里改了提案编号或锚点句，图测试会失败而不是悄悄留一张过期的图）。
